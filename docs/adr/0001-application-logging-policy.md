# Application logging policy

Qt logging categories remain the application's logging interface. All modules in this application write to one shared log file, and each record carries its category so playback, proxy, and live-message events can be read in one timeline. File logging is enabled by default at `info` level, with optional per-category overrides for diagnosis. A separate file-logging switch controls persistence without suppressing Qt's system output; settings changes take effect immediately, and the same values live in the user configuration directory. Startup environment overrides apply only to the current run. The settings interface offers Normal and Playback diagnostics modes; the latter enables `debug` for the player and proxy, while individual category rules remain available in the configuration file. File logs rotate at 10 MB, retaining the current file and three older files; disabling file logging retains existing files. Writing uses a bounded asynchronous queue so playback threads do not wait for disk writes. The worker flushes while idle and immediately after warnings or more severe records. When saturated, it discards `debug` and `info` first; if no lower-severity entries are available, it drops the oldest queued entry to keep producers nonblocking. It reports the total number discarded. Sensitive credentials, connection keys, and playback URL authentication parameters must be redacted. A file-logging failure must not interrupt playback and must be visible through system output and the settings interface. This policy keeps the existing Qt call sites while enabling targeted diagnostics for playback failures.
